# Картыч

Карты лояльности кафе, магазинов и студий в одном месте. Гость входит через MAX, копит баллы по QR. Точка выдаёт карты только после заявки и нашего подтверждения.

Сайт: https://195.19.7.201.sslip.io

## Как это работает

Все заходят **как гости**. Отдельной анкеты нет: первый вход через MAX создаёт аккаунт.

1. Гость на кассе жмёт **«Показать QR»** — кассир сканирует код и записывает покупку.
2. Или кассир показывает QR покупки, а гость сканирует его камерой.
3. Баллы и штампы копятся только в той точке, которая их начислила.
4. Списание и подарок тоже подтверждает кассир своим сканером.

Карта на экране «Рядом» показывает только **подтверждённые** точки. Тайлы OpenStreetMap, ключ API не нужен. Если OSM недоступен, подключается запасной слой Esri.

## Роли

| Кто | Как появляется | Что может |
| --- | --- | --- |
| **Гость** | Вход через MAX | Карты, лига, свой QR, поиск точек, сканер кассы |
| **Собственник** | Заявка + подтверждение админом | Кабинет точки: аналитика, QR, сканер, акции, меню, сотрудники |
| **Кассир** | Разовая ссылка от собственника | То, что отметили заранее. По умолчанию только сканер QR |
| **Админ платформы** | `ADMIN_MAX_USER_IDS` в `.env`, остальных добавляют на `/admin` | Подтверждать или отклонять заявки точек |

У собственника сверху справа **«Как гость»** — обычные карты и QR, точка никуда не девается. Обратно — **«К точке»**.

Тема по умолчанию светлая. Луна в шапке включает тёмную.

## Бизнес

Кабинет точки **не выбирается при входе**. Схема такая:

1. Зайти как гость.
2. Профиль → **Открыть точку**: название, сайт организации, адрес, метка на карте (клик или «Найти адрес»).
3. Заявка уходит админам в MAX и на `/admin`.
4. После «Подтвердить» открывается кабинет бизнеса. Только тогда точка видна на карте и может выдавать карты гостям.

Сотрудники: в кабинете **Сотрудники** ставишь права и график, создаёшь ссылку. Ссылка одноразовая. Человек открывает её в MAX — становится кассиром.

## Админы платформы

Первого админа один раз пропиши в `.env`:

```
ADMIN_MAX_USER_IDS=123456789
```

Это MAX id из профиля Картыча (строка «MAX …»). После входа в профиле появится **Заявки бизнеса**.

Второго админа добавляешь уже на `/admin`: человек заходит в Картыч, скидывает свой MAX id, ты вписываешь число. Снять его можно там же. Того, кто в `.env`, с сайта не убрать.

## Бот MAX

Кнопки: **Показать QR**, **Открыть кабинет**, **Поддержка**.  
Вход на сайт: бот подтверждает сессию, вкладка сама открывает кабинет.

## Локально

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
copy .env.example .env
docker compose up -d postgres redis
alembic upgrade head
uvicorn app.main:app --reload --port 8000
pytest
```

Демо-вход (только `APP_ENV=development` или `test`): на `/login` блок «Посмотреть демо».

Пока `PUBLIC_BASE_URL` не `https://...`, вебхук при старте не регистрируется.

## Прод

Код на VPS обновляется без правки `.env`, прокси и бота:

```bash
python -m scripts.update_vps
```

Скрипт заливает `app/` и `alembic/`, гоняет staging, делает бэкап SQLite и откатывается, если сервис не поднялся.

В MAX: URL мини-приложения `https://ДОМЕН/app`.

## Важные переменные

Смотри `.env.example`. Секреты в git не кладём.

| Переменная | Зачем |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен бота |
| `MAX_BOT_USERNAME` | Ник без `@` |
| `PUBLIC_BASE_URL` | Публичный HTTPS |
| `WEBHOOK_SECRET` | Подпись вебхука и сессии |
| `ADMIN_MAX_USER_IDS` | MAX id админов через запятую |
| `DATABASE_URL` | На VPS — SQLite в `/opt/cupcard/data/` |

API MAX: `https://platform-api2.max.ru`, заголовок `Authorization: <токен>` без Bearer.
